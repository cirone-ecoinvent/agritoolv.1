# Requirements for the ecoSpold writer (formerly: Java changes pending)

> Since decision O3 (docs/DECISIONS.md) the legacy Java code is not changed. This list is kept as
> the set of requirements the new ecoSpold2 writer of AgriToolV.1 must meet. File and class names
> refer to the legacy repository sri-crop-tool.

The fixes F1-F9 were applied to the Python model layer only (no JDK or Maven available on the
machine where the branch was produced). The ecoSpold2 writer (Java) still has to be adapted as
listed below; each item names the Python output keys it must consume. Until these edits are
made, the new Python outputs are ignored by the writer (they do not break it: unknown keys are
simply not read, and all pre-existing keys are still produced).

## F7 - flooded rice land flows

File: `src/main/java/com/quantis_intl/lcigenerator/ecospold/EcospoldTemplateSubstanceUsages.java`,
array `resources`. Add three entries (flows verified in Master Data v3.12,
`data/ecoinvent_flows_md312.csv`):

| Flow name | Subcompartment constant | Unit | Python output key | Uncertainty class |
|---|---|---|---|---|
| Occupation, annual crop, flooded crop | `RESOURCE_LAND` | `M2_YEAR` | `occupation_annual_flooded` | `LAND_OCCUPATION` |
| Transformation, from annual crop, flooded crop | `RESOURCE_LAND` | `M2` | `transformation_from_annual_flooded` | `LAND_TRANSFORMATION` |
| Transformation, to annual crop, flooded crop | `RESOURCE_LAND` | `M2` | `transformation_to_annual_flooded` | `LAND_TRANSFORMATION` |

The LUC exchange name `"land use change, " + luc_crop_type + " crop"` now receives
`luc_crop_type = annual` for rice (was `Paddy rice`, which matched no dataset).

## F6 - seed and seedling exchanges from the Master Data

File: `EcospoldTemplateIntermediaryExchanges.java`, array `materialsFuels`. The 110 static
`seeds_<crop>` entries (lines 27-495) are to be replaced by two template entries whose product
name is taken from the Python output (the template already supports `{variable}` substitution
in `TemplateIntermediaryExchange.provideName`):

```java
new TemplateIntermediaryExchange("{seed_exchange_name}", AvailableUnit.KG,
        "seed_amount_kg", StandardUncertaintyMetadata.SEEDS, "seeds"),
new TemplateIntermediaryExchange("{seed_exchange_name}", AvailableUnit.UNIT,
        "seed_amount_unit", StandardUncertaintyMetadata.SEEDS, "nb_seedlings"),
```

Python outputs (produced by `OutputMapping.mapSeeds` when the Master Data path is configured):
`seed_exchange_name`, `seed_exchange_uuid`, `seed_exchange_unit` (`kg` or `unit`), and exactly
one of `seed_amount_kg` / `seed_amount_unit` (trees and perennial seedlings already divided by
the orchard lifetime). `EcospoldFileWriter.buildIntermediateExchange` looks the name up in
`IntermediateExchanges.xml`; the UUID written must equal `seed_exchange_uuid` (same Master Data
version on both sides) - add an assertion. The legacy triplets "planting tree" /
"establishing orchard" are not covered by the mapping and need a separate decision.

## F9 - flow and product names aligned with Master Data 3.12

The user decided on 2026-10-09 that the terminology must follow the Master Data. The target
names, UUIDs and units are in two review tables of the repository, generated by
`scripts/check_master_data.py` from `MasterData (3.12, undef).xlsx`:

- `data/elementary_flow_alignment.csv` (402 flows): edit `EcospoldTemplateSubstanceUsages.java`
  (arrays `toWater`, `toSoil`) and `ecospold_pesticides_substance_mapping.properties` so that
  every name equals `md312_name`. Already final: `Cadmium, ion` / `Cadmium` -> `Cadmium II`;
  `Lead` -> `Lead II`; `Mercury` -> `Mercury II`; `Nickel, ion` / `Nickel` -> `Nickel II`;
  `Zinc, ion` / `Zinc` -> `Zinc II`; `Copper, ion` -> `Copper ion` (soil keeps `Copper`,
  which exists in 3.12); pesticide names that differ only by capitalisation.
  Open: Chromium III or VI; 8 pesticide proposals; Cyfluthrin, Pyrethrine, Pyrethrum; Metiram.
- `data/intermediate_exchange_alignment.csv` (587 products): edit
  `EcospoldTemplateIntermediaryExchanges.java` and
  `ecospold_pesticides_product_mapping.properties`. Open: mineral fertilisers "..., as N /
  P2O5 / K2O" (generic "inorganic ... fertiliser" with the same basis, or product in kg, which
  needs a nutrient-content conversion in Python), lime, ammonia, transport, triazine-compound.
- Unit bug: `land use change, annual crop` / `perennial crop` are in `ha` in the Master Data;
  the writer declares `AvailableUnit.KG` for the LUC exchange (`LucTemplateIntermediaryExchange`).
  The amount computed by the formula is already an area share per kg of product, so only the
  unit must change to `AvailableUnit.HA`. Master Data 3.12 also has
  `land use change, paddy rice` (ha): to be decided whether rice should use it (F7).

Apply the Java edits only for rows whose status is final (`scripts/review_status.py`).
